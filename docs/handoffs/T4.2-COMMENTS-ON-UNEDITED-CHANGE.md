# T4.2 — Review comments vanish on a change with no edits

**Task:** T4.2 · **Track:** T4 Control & git · **Size:** S · **Branch:** `t4/review-snapshot-branch` · **Needs:** nothing · **Issue:** [#28](https://github.com/fearjet44/revdesk/issues/28)
**Read first:** `AGENTS.md`, then in `server/git.ts` `snapshotReview`, `changeBranchTip`, `readReviewNotes`, `writeReviewNotes`, `copyReviewNotes`; in `server/repo.ts` `reviewSection`, `addComment`, `answerComment`, `snapshotChangeReview`; then `scripts/review-comments-check.sh`.

## Goal

Found while smoking #27. A reviewer comments on a change whose working sections are identical to the issued text. No comment ever shows, on either desk, and each new comment replaces the last.

Cause: `snapshotReview` finds the new tree equals the parent's tree and returns `{ commit: parent, reused: true }` **without creating `refs/heads/change/<id>`**. `addComment` writes the notes on `parent` (the library's HEAD). `readReviewNotes` reads from `changeBranchTip`, which is null, so it returns nothing. The next `addComment` reads "no existing comments" and overwrites the note.

A change with a saved edit is not affected: its first snapshot makes a new commit and creates the branch.

## Done when

- [ ] When `snapshotReview` reuses the parent and the change branch does not exist, it creates the branch at the parent (`update-ref`, the same call the non-reused path uses). An existing branch is never moved backwards or rewritten.
- [ ] After a comment on an unedited change:
  - `reviewSection` and `listComments` return it
  - a second comment keeps the first (both are in the note)
  - after `change return-to-edit`, the author side lists both and `answerComment` works on them
  - then editing a section and resubmitting carries both comments to the new snapshot (`copyReviewNotes`, as today)
- [ ] A change with edits behaves exactly as before.
- [ ] `scripts/review-comments-check.sh` gets a case for the steps above. Make it fail on `origin/main` and pass with the fix; say in the PR that you saw both. Use the CLI the script already drives, in its isolated temp repo.
- [ ] `npx tsc -b`, `npm run lint`, and the T4 tests from the ROADMAP pass: `npm run test:slice2`, `test:slice3`, `test:slice9`, `test:slice10`, `test:review`.

## Do not

- Migrate or clean up notes already written on a HEAD commit. They are local smoke dirt; the operator removes them.
- Change the notes format, the notes ref, or the branch name pattern.
- Block submitting a change with no edits. Whether that should be allowed is a separate question; list it in the PR if you have a view.
- Touch UI copy (T3) or any `src/` file.
