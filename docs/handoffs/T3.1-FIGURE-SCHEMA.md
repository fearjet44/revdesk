**Task:** T3.1 · **Track:** T3 Editor & figures · **Size:** M · **Branch:** `t3/figure-schema` · **Needs:** W0 and T3.3 (bullets) merged; both edit `src/schema/markdown.ts`, and T3 runs one task at a time
**Read first:** `AGENTS.md`, **`docs/plan/figures.md` (the contract; follow it exactly)**, `docs/plan/mermaid.md`, then the mermaid implementation, which this task copies the shape of: `src/schema/markdown.ts` (`isMermaidOpen`, the mermaid branches in `parseBody` / `isBlockStart` / `serializeBlock`), `src/schema/extensions.ts` (`Mermaid`), `src/schema/mermaid-view.ts`, `server/print.ts` (`renderNode` `case 'mermaid'`), and `scripts/mermaid-check.ts`.

## Goal

Real manuals carry pictures (org charts, photos, form facsimiles). T2.2 will import them from Word. This task makes a figure a first-class block: it parses, round-trips, shows in the editor and on the Issued rail, prints into the PDF, and is stored the content-addressed way the contract says. **Inserting** a figure from the editor toolbar is T3.2, not this task.

## Done when

- [ ] **Markdown** (`src/schema/markdown.ts`): a line matching the contract's block form, `^!\[(caption)\]\((figures/[0-9a-f]{12}\.(png|jpg|gif|svg|webp))\)(\{width=(25|50|75|100)%\})?\s*$`, parses to `{ type: 'figure', attrs: { src, caption, width } }`.
  - `isBlockStart` knows it, so a figure line ends the paragraph above it.
  - `serializeBlock` writes it back, emitting `{width=…}` only when the width is not `100%`.
  - Captions containing `]` are escaped as `\]` on write and unescaped on read.
  - Anything that doesn't match (inline image, `../`, http URL, other extension) stays paragraph text, exactly as today.
- [ ] **Storage** (`server/figures.ts`, new):
  - `figureName(bytes, ext): string` → `<sha256 first 12 hex>.<ext>`, normalizing `jpeg` to `jpg`.
  - `writeFigure(dataRoot, manualId, bytes, ext): { src: string; existed: boolean }`. Write-once, under `manuals/<id>/figures/`. Throws `RepoError(2)` for a bad type or a file over 10 MB.
  - `readFigure(dataRoot, manualId, file): { bytes: Buffer; mime: string } | null`. It validates `file` against the contract regex before touching disk.
  - It never deletes and never overwrites.
- [ ] **API** (`server/plugin.ts`, additive, next to the other `manuals` routes):
  - `GET /api/manuals/:id/figures/:file` → bytes, `Content-Type` from the extension, `Cache-Control: public, max-age=31536000, immutable`; SVG also gets `Content-Security-Policy: script-src 'none'`; 404 when the name is invalid or the file is missing.
  - `POST /api/manuals/:id/figures` `{ filename, content }` (base64, same convention as `uploadedBook`) → `201 { src, bytes, existed }`.
  - The manual id must exist (`repo.getManual`, 404 otherwise).
- [ ] **Editor and Issued:**
  - New `Figure` node in `src/schema/extensions.ts`: atom, block, selectable, attrs `src`/`caption`/`width`, with a node view in a new `src/schema/figure-view.ts`.
  - The node view draws `<figure class="figure"><img src="/api/manuals/<manualId>/figures/<file>"><figcaption>`. A missing image (`onerror`) shows the "Figure missing: <file>" box.
  - The caption is editable in the editor (plain `<input>` or a contenteditable figcaption, written back with `updateAttributes`) and read-only when the editor isn't editable.
  - The manual id comes from extension options. Add `buildEditorExtensions({ manualId })` and keep `export const editorExtensions = buildEditorExtensions({ manualId: '' })` so the scripts that import it keep working. Switch `SectionEditor.tsx`, `IssuedSection.tsx`, and `ManagedSection.tsx` to `buildEditorExtensions({ manualId })` with the id they already have.
  - CSS in `src/index.css`: centered, `max-width: 100%`, the width classes, a small caption, the missing-box style. Use the theme variables the callouts use.
- [ ] **Print** (`server/print.ts`):
  - `renderNode` gains `case 'figure'`, emitting the contract's `<figure class="figure" style="width:…"><img src="data:<mime>;base64,…" alt=""><figcaption>…</figcaption></figure>`.
  - The bytes come from a resolver passed in. Add an optional `figure?: (src: string) => { bytes: Buffer; mime: string } | null` to the `buildManualHtml` opts. The plugin's PDF routes pass `(src) => readFigure(repo.root, manualId, path.basename(src))`. When the resolver is absent or returns null, print the missing box, never a broken `<img>`.
  - Print CSS: `break-inside: avoid`; `img { max-width: 100%; }`.
- [ ] **Tests:** new `scripts/figures-check.ts`, appended to `test:md` in `package.json`, covering:
  - round-trip (parse → serialize → parse is stable) with and without a width and with a caption containing `]`
  - invalid forms stay paragraphs
  - a figure line ends a paragraph
  - `figureName` is deterministic and `writeFigure` is write-once (second call `existed: true`, mtime unchanged)
  - `readFigure` refuses `../x.png`, `ABC.png`, and `x.exe`
  - `buildManualHtml` with a resolver contains `data:image/png;base64`; without one, it contains the missing box

  Use a tiny generated PNG (a hard-coded 1×1 PNG base64 string in the test). **Do not add an image to `data/` or `fixtures/`.**
- [ ] `npx tsc -b`, `npm run lint`, `npm run test:md` (including the existing `mermaid-check`, `steps-check`, `theme-check`, `pdf-check`), and `npm run test:slice10` pass.
- [ ] Manual check: on a scratch library copy, hand-write a figure line into a leaf, put a PNG at the hashed name, and confirm it shows in the editor and on Issued and prints in the PDF. Say in the PR what you saw.
