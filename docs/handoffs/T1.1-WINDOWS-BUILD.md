# T1.1 — Windows build + runtime

**Task:** T1.1 · **Track:** T1 Platform · **Size:** M · **Branch:** `t1/windows-build` · **Needs:** W0 merged
**Read first:** `AGENTS.md`, `docs/plan/ROADMAP.md`, `docs/runbook/desktop.md`, `src-tauri/src/lib.rs`.

## Goal

An early user is on Windows. CI should produce a Windows installer, and that installer should run the desk on a stock Windows 10/11 machine where Node, Git, qpdf, and poppler were installed with winget. Edge renders the PDFs (W0's `toolPath('chrome')` already finds `msedge.exe`).

Prerequisites are **not bundled** in this task (that's parked). T1.2 adds the in-app prerequisites screen later. This task only makes sure the app finds what winget installed and fails with a clear message when something is missing.

## Done when

- [ ] `.github/workflows/desktop.yml` has a third matrix row: `os: windows-latest`, `target: x86_64-pc-windows-msvc`, `bundles: nsis`. The upload step includes `src-tauri/target/${{ matrix.target }}/release/bundle/nsis/*.exe`. All three rows are green on the PR.
- [ ] `src-tauri/src/lib.rs`, Windows only (`cfg!(windows)` / `#[cfg(windows)]`). macOS and Linux behavior is byte-for-byte the same:
  - `find_node()`: after `REVDESK_NODE` and PATH, try `%ProgramFiles%\nodejs\node.exe`, then `%LOCALAPPDATA%\Programs\nodejs\node.exe`, then `%NVM_SYMLINK%\node.exe` (nvm-windows). Skip a candidate whose env var is unset.
  - The node sidecar `Command` gets `creation_flags(0x0800_0000)` (`CREATE_NO_WINDOW`) via `std::os::windows::process::CommandExt`, so no console window appears behind the app.
  - `tool_path()`: on Windows, prepend node's own dir and `%ProgramFiles%\Git\cmd`. Do not add the Homebrew dirs there. Keep `env::join_paths`, which already uses `;`.
  - The "needs Node" error names the right installer per OS: macOS `brew install node`, Windows `winget install OpenJS.NodeJS.LTS`, Linux "your package manager".
- [ ] `server/config.ts`: on `process.platform === 'win32'`, `userConfigPath()` is `%APPDATA%\revdesk\config.yaml` and `defaultClonePath()` is under `%LOCALAPPDATA%\revdesk\libraries\`. **`XDG_CONFIG_HOME` / `XDG_DATA_HOME` still win when set** (the slice-7 tests set them). macOS and Linux paths unchanged.
- [ ] `src-tauri/tauri.conf.json`: add `bundle.windows.nsis.installMode: "currentUser"` (no admin prompt). Keep the WebView2 install mode at its default. Confirm the `.ico` is picked up.
- [ ] `docs/runbook/desktop.md`: a **Windows** section covering:
  - download the `revdesk-x86_64-pc-windows-msvc` artifact from the Actions run (Summary → Artifacts)
  - the SmartScreen "More info → Run anyway" step (the installer is unsigned)
  - the winget prerequisite line
  - the `REVDESK_*` overrides from W0
  - known gaps
- [ ] The winget package IDs in the runbook were **checked against `winget search` output or winget-pkgs**, not guessed. Starting points to verify: `OpenJS.NodeJS.LTS`, `Git.Git`, `QPDF.QPDF`, `oschwartz10612.Poppler`. If poppler has no reliable winget package, document the zip path plus `REVDESK_POPPLER_DIR` instead.

## Do not

- Bundle Node, qpdf, poppler, or Chrome, or download anything at runtime.
- Add code signing or secrets to CI.
- Change macOS or Linux code paths, the `.dmg` row, or the Linux row (other than what the matrix needs).
- Touch `server/tools.ts`. If W0's resolver misses a Windows location, say so in the PR; a W0 follow-up fixes it.
- Run the bash acceptance scripts on the Windows runner.

## Hints

- `#[cfg(windows)] use std::os::windows::process::CommandExt;` then `cmd.creation_flags(0x0800_0000);`. Build the `Command` in a `let mut cmd` first so the cfg block can reach it.
- `windows-latest` runs PowerShell by default. `npm ci` and `npx tauri build …` work as-is. If a step needs bash, set `shell: bash` on that step only.
- `swatinem/rust-cache` and `actions/setup-node` `cache: npm` work on Windows unchanged.
- The release app already sets `windows_subsystem = "windows"` (`src-tauri/src/main.rs`). The console flag is only needed for the child.
